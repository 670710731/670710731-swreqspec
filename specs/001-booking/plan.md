# แผนทางเทคนิค: จองคิวตรวจสุขภาพ (Booking)

- Spec ID: SPEC-BKG-001
- Spec version: Draft v2
- สถานะ: รอทีมตรวจสอบ
- เทคโนโลยี: ใช้ MySQL ตาม CON-TECH-01; ภาษาและ framework ทีมเลือกเอง ไม่ได้มาจาก spec

## 1. สรุปแนวทาง

ฟีเจอร์นี้ให้ผู้รับบริการที่ยืนยันตัวตนแล้วเลือกแพ็กเกจ วัน และช่วงเวลาตรวจสุขภาพเพื่อรับหมายเลขคิว (Goal, FR-BKG-01, FR-BKG-04)
ระบบจะแสดงช่วงเวลาที่ว่างภายใน 30 วันพร้อมจำนวนที่นั่งคงเหลือ และคำนวณใหม่เมื่อเปลี่ยนแพ็กเกจ (FR-BKG-01, FR-BKG-06)
ระบบจะตรวจคิวเดิมของผู้รับบริการในวันเดียวกันก่อนยืนยัน และป้องกันการจองเมื่อมีคิวที่ยังไม่ได้ใช้ (FR-BKG-02, ASM-02, ASM-03)
การยืนยันจะบันทึกการจอง ตัดที่นั่ง และออกหมายเลขคิวตามลำดับ โดยหมายเลขคิวรีเซ็ตทุกวัน (FR-BKG-04, ASM-05)
หลังบันทึกการจอง ระบบจะส่งคำขอข้อความแบบ asynchronous และส่งซ้ำตามรอบจนกว่าจะสำเร็จ (FR-BKG-05, IF-NOT-01, NFR-REL-02, ASM-09)

| React (Vite) | ทีมเลือกเอง ไม่ได้มาจาก spec | ใช้สำหรับหน้าบ้านตามค่าเริ่มต้นของรายวิชา |

| TLS 1.2 ขึ้นไป | NFR-SEC-01 | ใช้กับการรับส่งข้อมูลการจอง |

## 3. โมเดลข้อมูล

| Entity | ฟิลด์หลัก | รองรับ |
|---|---|---|
| Package | package_id, package_name, time_slot_rule | FR-BKG-01, FR-BKG-06 |
| TimeSlot | slot_id, service_date, start_time, end_time, quota, remaining_seats | FR-BKG-01, FR-BKG-03, FR-BKG-04, ASM-01 |
| Booking | booking_id, hn, package_id, slot_id, service_date, queue_number, status, created_at | FR-BKG-02, FR-BKG-04, FR-BKG-05, ASM-02, ASM-03, ASM-05 |
| NotificationJob | notification_id, booking_id, channel, status, retry_at | FR-BKG-04, FR-BKG-05, IF-NOT-01, NFR-REL-02 |
| AuditLog | audit_id, accessor, accessed_at, patient_code | DOM-PDPA-01, AC-BKG-06 |

หมายเหตุด้านข้อมูล:

- `Booking` ใช้ `hn` เป็นข้อมูลอ้างอิงภายในระบบตาม IF-HIS-01 และไม่มีฟิลด์เลขบัตรประชาชน (IF-HIS-01)
- ข้อมูลผู้รับบริการต้องได้มาหลังได้รับผลยืนยันตัวตนจาก IDP (IF-IDP-01)
- `TimeSlot` อ้างอิงโควตาที่จัดการโดย UC-09 และแผนนี้ไม่สร้างส่วนจัดการตารางหรือโควตา (ASM-01, Out of scope)
- `Booking` ต้องรองรับสถานะคิวหมดเวลาหรือผู้รับบริการไม่มาตามนัดว่าเป็นคิวที่ยังไม่ได้ใช้ (ASM-03)

## 4. API / หน้าจอ

- `GET /booking/availability` รับ package_id และช่วงวันที่; ส่งวัน ช่วงเวลา และจำนวนที่นั่งคงเหลือภายใน 30 วัน (FR-BKG-01)
- `POST /booking/availability/recalculate` รับ package_id และช่วงเวลาเดิม; ส่งช่วงเวลาที่ว่างใหม่และช่วงเวลาเดิมเมื่อยังว่าง (FR-BKG-06, ASM-04)
- `POST /booking/validate` รับ HN วัน และช่วงเวลาที่เลือก; ส่งผลคิวเดิมหรือผลพร้อมยืนยัน (FR-BKG-02, ASM-02, ASM-03)
- `POST /booking/confirm` รับ HN package_id และ slot_id; ส่งสถานะการจอง หมายเลขคิว และจำนวนที่นั่งคงเหลือ หรือแจ้งช่วงเวลาเต็ม (FR-BKG-03, FR-BKG-04, AC-BKG-01, AC-BKG-03)
- หน้าจอเลือกแพ็กเกจและช่วงเวลา แสดงวันภายใน 30 วัน จำนวนที่นั่ง และผลคำนวณใหม่ (FR-BKG-01, FR-BKG-06)
- หน้าจอผลการจอง แสดงหมายเลขคิวเมื่อสำเร็จ หรือหมายเลขคิวเดิม/ช่วงเวลาเต็มตามผลการตรวจ (FR-BKG-02, FR-BKG-03, FR-BKG-04, FR-BKG-05)
- Worker ส่ง `NotificationJob` แบบ asynchronous และกำหนดส่งซ้ำภายใน 5 นาทีเมื่อส่งไม่สำเร็จ (IF-NOT-01, FR-BKG-05, NFR-REL-02)

เมื่อ IDP/HIS ไม่ตอบสนอง ไม่พบข้อมูล หรือข้อมูลผิดรูปแบบ ให้หยุดการจอง แสดงข้อผิดพลาดเพื่อให้ลองใหม่ และไม่สร้างรายการจอง (IF-IDP-01, IF-HIS-01, ASM-08)

## 5. ตารางตรวจ Constraints

| Constraint ID | ถูกนำไปใช้ที่ไหนใน plan | สถานะ |
|---|---|---|
| CON-TECH-01 | ตารางเทคโนโลยีเลือก MySQL และโมเดลข้อมูลใช้กับฐานข้อมูลนี้ | ใช้แล้ว |
| DOM-PDPA-01 | Entity `AuditLog`, การบันทึกผู้เข้าถึง เวลา รหัสผู้รับบริการ และการทดสอบ AC-BKG-06 | ใช้แล้ว |
| IF-IDP-01 | ขั้นตอนก่อนเข้าถึงข้อมูลผู้รับบริการ และหยุดการจองเมื่อ IDP ผิดพลาด | ใช้แล้ว |
| IF-HIS-01 | ใช้ HN ใน `Booking`, ไม่เก็บเลขบัตรประชาชน และหยุดการจองเมื่อ HIS ผิดพลาด | ใช้แล้ว |
| IF-NOT-01 | `NotificationJob` และ Worker ส่งข้อความแบบ asynchronous ผ่านช่องทางที่ผู้รับบริการกำหนดและส่งซ้ำจนสำเร็จ | ใช้แล้ว |

## 7. ลำดับงาน

1. ตรวจสอบ spec v2 และยืนยัน ASM-06 ถึง ASM-11 ก่อนเริ่ม implementation (ASM-06 ถึง ASM-11)
2. สร้างโมเดล `Package`, `TimeSlot` และการอ่านข้อมูลโควตาจาก UC-09 (FR-BKG-01, ASM-01)
3. สร้างการค้นหาและหน้าจอแสดงช่วงเวลาว่างภายใน 30 วัน (FR-BKG-01, AC-BKG-05)
4. สร้างการคำนวณช่วงเวลาใหม่เมื่อเปลี่ยนแพ็กเกจ โดยรักษาช่วงเวลาเดิมเมื่อยังว่าง (FR-BKG-06, ASM-04)
5. เชื่อม IDP/HIS ตรวจ HN กับคิวเดิม และหยุดการจองเมื่อระบบภายนอกผิดพลาด (IF-IDP-01, IF-HIS-01, FR-BKG-02, AC-BKG-02, ASM-08)
6. สร้างการยืนยันแบบการดำเนินการเดียว ตรวจที่นั่ง บันทึกการจอง และออกหมายเลขคิวรายวัน (FR-BKG-03, FR-BKG-04, AC-BKG-01, AC-BKG-03, ASM-05, ASM-06, ASM-07)
7. สร้าง `NotificationJob` และ Worker แบบ asynchronous ใช้ช่องทางที่ผู้รับบริการกำหนดและส่งซ้ำจนสำเร็จ (IF-NOT-01, FR-BKG-05, AC-BKG-04, NFR-REL-02, ASM-09)
8. เพิ่ม TLS และ audit log พร้อมตรวจการเก็บ log ไม่น้อยกว่า 1 ปี (NFR-SEC-01, DOM-PDPA-01, AC-BKG-06)
9. รันทดสอบการใช้งาน ประสิทธิภาพ และ traceability ตาม AC ทั้งหมด (NFR-USE-01, NFR-PERF-01, ASM-10, ASM-11, AC-BKG-01 ถึง AC-BKG-06)
